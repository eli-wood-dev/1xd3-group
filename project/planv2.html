Names

The members of team SEGA are Eli Wood, Shreyas Hegde, Gurbaz Sogi, and Aaryn Gill. Our client is 4S Solutions, which is owned by Donny Sousa, who we are communicating with. The name of the project is the 4S Solutions Excavating Website.

Purpose

The purpose of the website is to serve as a landing page for anyone interested in hiring the 4S excavating service or renting their machines. The site will have a main landing page, a page containing which machines are in use or reserved at specified times, a page to send a message asking to rent a machine or service, and an admin page to read messages. We decided to add the functionality of the admin page and sending messages directly through the site to streamline the user experience and to make the users more likely to actually reach out.

Data Description

The database will have 4 tables, Users, Messages, Machines, and MachineRentals.

Messages

The messages table is necessary to store all of the messages that the users send which will be viewed on the admin page. The table will store the contents of the message and contact information for the user sending the message as well as timestamps. The table will also store if a message has been resolved or not, so that the admin can easily filter messages to only show unresolved messages.

PK int text varchar varchar varchar boolean timestamp timestamp varchar
id content email name phone_number resolved created_at resolved_at category

Machines

The machines table will store all of the machines owned by 4S Solutions. The table will store the name of the machine, a description, and a link to an image.

PK int varchar text varchar
id name description image

MachineRentals

The machine rentals table will store when specific machines are in use and when they become available. The table will store the start date, the end date, and a foreign key which references which machine is in use.

PK int FK int date date
id machine_id start_date end_date

Users

The users table will store valid administrator users to allow for logging in to the admin mode. The table will store the email, name, and password of the admin users. The passwords are stored in a hashed format.

PK int varchar varchar varchar
id email name password

Functions Performed by the App

Send Messages

Users sending messages will use an INSERT query on the messages table to add the message and all other info.

Read Messages

Reading messages from the admin page will use a SELECT query to get all unresolved messages. There is an option to filter the messages to show only unresolved, resolved, or both.

Toggle Message Resolved

Resolving and unresolving messages from the admin page will use an UPDATE query to toggle the resolved status of a specific message.

View Machines

Viewing machines will use a SELECT query to view all machines. This will also SELECT from MachineRentals to display if the specified machine is available or in use.

Increments

The project will have 2 main increments, the first delivery on April 7, and the final deliverable on April 19. The first increment will have a landing page, the ability to enter admin mode, the ability to send messages, a simple admin view for messages, and a listing of all machines stating when they are in use. By the final deliverable we will finalize styling, polish the messaging system by implementing resolved vs unresolved messages, and make the machine listing fully show date ranges when each machine is available or in use. Much of the content for the final deliverable was finished in time for the first delivery, so the final delivery will focus more on polish and creating a consistent site feel.

Client Feedback

Development Plan Feedback

When we presented the development plan to the client they liked it, but they had some minor feedback. They said that the content on some of the wireframes seemed like it might need to change, but we discussed that the wireframes are temporary and will not necessarily be what the final page looks like. The second piece of feedback was that they were surpised by the messaging system, and they did not think it would be fully necessary, but they said it was a good idea and that "We would like to see what you guys do with it as we can see how it would make it easier for clients to get a hold of us." Overall they were happy with the development plan and did not suggest any major changes.

First Increment Feedback

Our client had some feedback on the first increment we made. This is what they had to say about our project: Overall we are very pleased with the progress of the site so far. The design is very easy to navigate, and the information is presented in an orderly fashion. We will obviously need to tweak the placeholder text, and its possible we may need to meet again to modify some formatting here and there, but that will have to be well in the future as we don't yet have the content written up that we'd like to include on the site. One thing to note is that it'd be nice if the scheduling/booking dates for the machines were shown in a calendar, or at least in a more organized table.
